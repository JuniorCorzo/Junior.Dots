# OpenSpec + Superpowers Integration Design

**Date:** 2026-09-07  
**Status:** Draft — pending user review  

---

## Goal

Integrate OpenSpec into the Superpowers agentic workflow so that all specs, plans, and implementation artifacts live in a single repo-tracked Change Folder that is readable by any AI coding tool (Cursor, Claude Code, Antigravity, GitHub Copilot, etc.) — eliminating dependency on a specific agent or chat session for context.

---

## Architecture

Superpowers remains the orchestration layer (entry point is always `brainstorming`). OpenSpec provides the **artifact format and lifecycle** (Change Folder structure + sync/archive commands). The two systems integrate at exactly two seams:

1. **Output of `brainstorming`** — generates a Change Folder instead of a flat spec doc.
2. **Step 0 of `finishing-a-development-branch`** — runs `opsx:sync` + `opsx:archive` before the merge/PR menu.

`subagent-driven-development` is unchanged.

### Full Flow

```
brainstorming (architectural path)
    └─► Change Folder: .openspec/changes/YYYY-MM-DD-<feature>/
            ├── proposal.md   (goal + rationale)
            ├── design.md     (full technical spec)
            ├── tasks.md      (atomic checklist)
            └── specs/        (delta specs per component)
    │
    ▼
writing-plans
    reads tasks.md as task source
    generates plan.md inside the SAME Change Folder:
    .openspec/changes/YYYY-MM-DD-<feature>/plan.md
    │
    ▼
subagent-driven-development  (unchanged)
    reads plan.md + design.md from Change Folder
    │
    ▼
finishing-a-development-branch
    Step 0 (NEW): opsx:sync → opsx:archive
    Step 1+: existing verify/detect/menu flow
```

## Repo Structure

```
<repo-root>/
├── .openspec/
│   ├── system/                        ← global spec master (source of truth)
│   │   └── *.md
│   ├── changes/                       ← active Change Folders (one per in-flight feature)
│   │   └── YYYY-MM-DD-<feature>/
│   │       ├── proposal.md
│   │       ├── design.md
│   │       ├── tasks.md
│   │       ├── plan.md                ← generated by writing-plans
│   │       └── specs/
│   │           └── <component>.md    ← ADDED / MODIFIED / REMOVED
│   └── archive/                       ← completed features (permanent audit trail)
│       └── YYYY-MM-DD-<feature>/      ← full Change Folder preserved
├── .superpowers/sdd/                  ← git-ignored SDD scratch (unchanged)
└── docs/superpowers/                  ← DEPRECATED for new features; legacy ok
```

**`.openspec/` is committed to git.** It is the multi-tool source of truth.  
**`.superpowers/sdd/`** remains git-ignored scratch for SDD execution — no change.  
**`docs/superpowers/`** is deprecated for new features. Existing docs are left as-is.

### Initialization (once per repo)

```bash
npm install -g @fission-ai/openspec@latest
openspec init
```

`brainstorming` checks for `.openspec/` at the start of the architectural path. If absent, it instructs the user to run `openspec init` before proceeding.

## Component Changes

### 1. `brainstorming` skill

**Path:** `skills/brainstorming/SKILL.md`

**Changes to the architectural path:**

- **Documentation section** replaces the current save target:
  - Old: `docs/superpowers/specs/YYYY-MM-DD-<topic>-design.md`
  - New: `.openspec/changes/YYYY-MM-DD-<feature>/` (full Change Folder)

- **Change Folder contents generated by brainstorming:**
  - `proposal.md` — goal sentence + rationale (maps to current "Goal" section of spec)
  - `design.md` — full technical spec (same structure and depth as today's spec doc)
  - `tasks.md` — atomic checklist derived from the design, formatted for `writing-plans` consumption
  - `specs/` — one `.md` per affected component, marked ADDED / MODIFIED / REMOVED

- **Spec self-review** gains two extra checks:
  1. `tasks.md` is coherent with `design.md` — no task references a component not in the design
  2. Every delta spec in `specs/` is correctly tagged (ADDED/MODIFIED/REMOVED)

- **User Review Gate** asks the user to review the full Change Folder:
  > "Change Folder written to `.openspec/changes/YYYY-MM-DD-<feature>/`. Please review `proposal.md`, `design.md`, and `tasks.md` before I invoke `writing-plans`."

- **Pre-flight check:** if `.openspec/` does not exist in the repo root, stop and instruct:
  > "OpenSpec is not initialized in this repo. Run `openspec init` first, then let me know to continue."

### 2. `writing-plans` skill

**Path:** `skills/writing-plans/SKILL.md`

**Changes:**

- **Task source:** reads `tasks.md` from the Change Folder as the starting task list instead of generating tasks from scratch. Enriches each task with: actual test code, run commands, interface signatures, and commit steps (TDD cycle).

- **Save target:** generates `plan.md` inside the active Change Folder:
  - Old: `docs/superpowers/plans/YYYY-MM-DD-<feature>.md`
  - New: `.openspec/changes/YYYY-MM-DD-<feature>/plan.md`

- **Plan header `Spec:` field** points to `.openspec/changes/YYYY-MM-DD-<feature>/design.md`.

- **Fallback:** if no Change Folder is found (legacy repos), falls back to current behavior. Zero breaking change.

### 3. `finishing-a-development-branch` skill

**Path:** `skills/finishing-a-development-branch/SKILL.md`

**Single change — insert Step 0 before the current Step 1:**

```
## Step 0: OpenSpec Sync & Archive (if applicable)

Detect whether an active Change Folder exists for this branch:

1. Look for `.openspec/changes/` in the repo root.
2. Match the Change Folder to the current branch or plan file
   (the plan's header carries the Change Folder path).
3. If a matching Change Folder is found:
   a. Run `opsx:sync`    — updates `.openspec/system/` with completed changes
   b. Run `opsx:archive` — moves the Change Folder to `.openspec/archive/`
4. If no matching Change Folder is found → skip silently.

This step runs BEFORE verify-tests. Archiving records what was built,
regardless of whether the merge/PR subsequently succeeds.
```

**Compatibility:** repos without `.openspec/` → Step 0 is a no-op.

## Data Flow Summary

| Artifact | Created by | Read by | Lives in |
|---|---|---|---|
| `proposal.md` | `brainstorming` | human reviewer, other tools | `.openspec/changes/<f>/` |
| `design.md` | `brainstorming` | `writing-plans`, SDD subagents | `.openspec/changes/<f>/` |
| `tasks.md` | `brainstorming` | `writing-plans` | `.openspec/changes/<f>/` |
| `specs/*.md` | `brainstorming` | other AI tools (multi-tool) | `.openspec/changes/<f>/specs/` |
| `plan.md` | `writing-plans` | SDD (implementer subagents) | `.openspec/changes/<f>/` |
| SDD ledger | `subagent-driven-development` | SDD controller | `.superpowers/sdd/<plan>/` (git-ignored) |
| `.openspec/system/` | `opsx:sync` | all tools (global source of truth) | `.openspec/system/` |
| `.openspec/archive/<f>/` | `opsx:archive` | audit, retrospectives | `.openspec/archive/` |

## Compatibility & Migration

- **New repos:** run `openspec init` once, then use the new flow end-to-end.
- **Existing repos with `docs/superpowers/`:** old plans and specs remain untouched. New features use the new flow. No migration required.
- **Repos without OpenSpec:** `brainstorming` detects missing `.openspec/` and stops. `writing-plans` and `finishing-a-development-branch` degrade gracefully.
- **Other AI tools:** because `.openspec/` is committed, Cursor / Claude Code / Copilot can read `design.md`, `tasks.md`, and `plan.md` directly without any Superpowers context.

---

## Out of Scope

- `opsx:explore` and `opsx:propose` slash commands — OpenSpec's own entry points are not integrated; `brainstorming` is the sole entry point.
- Automatic detection of which Change Folder matches which branch beyond reading the plan header.
- Migration tooling for existing `docs/superpowers/` content.
